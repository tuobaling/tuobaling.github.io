Hermes Desktop × Tailscale 遠端連線設定與故障排除

環境：Windows、Hermes Agent 0.23.1、Tailscale、hermes-tailscale

1. 整體架構

flowchart TB
    subgraph A["電腦 A：xxxx（Windows）"]
        Agent["Hermes Agent"]
        Gateway["Hermes Gateway
127.0.0.1:9119"]
        Serve["Tailscale Serve
HTTPS Reverse Proxy"]
        Data["Sessions / Profiles / 設定資料"]
        Agent --- Gateway
        Gateway --- Data
        Gateway --- Serve
    end

    subgraph B["電腦 B：遠端操作端"]
        Desktop["Hermes Desktop"]
        TailB["Tailscale Client"]
        Desktop --- TailB
    end

    TailB <-->|"Tailnet 私有 HTTPS"| Serve

核心觀念： hermes-tailscale 外掛不是 Gateway 本身。遠端連線真正依賴的是 Hermes Gateway、Tailscale Serve 與 Hermes Desktop 的 Remote Gateway 設定。

2. 安裝與初始設定

2.1 前置條件

2.2 安裝 hermes-tailscale

GitHub 專案：

https://github.com/Adolanium/hermes-tailscale

在支援外掛管理指令的 Hermes 版本中，可使用：

PLAIN
hermes plugins install hermes-tailscale

Windows 手動安裝路徑：

PLAIN
%USERPROFILE%\.hermes\desktop-plugins\hermes-tailscale\plugin.js

安裝後：

  1. 開啟 Hermes Desktop。

  2. 查看左側是否出現 Tailscale。

  3. 如未顯示，使用 Ctrl + K 搜尋 Reload desktop plugins。

  4. 必要時重新啟動 Hermes Desktop。

安裝方式為專案提供的方法；本次紀錄未包含實際安裝指令的執行輸出，因此不將安裝步驟標為已實測。

2.3 設定 Tailscale Serve

在電腦 A 啟動 Hermes Gateway：

PLAIN
hermes serve --host 127.0.0.1 --port 9119

設定 Tailscale Serve：

PLAIN
tailscale serve --bg 9119

查看 Serve 狀態：

PLAIN
tailscale serve status

本次實際結果：

PLAIN
https://xxxx.tailea6007.ts.net (tailnet only)
|-- / proxy http://127.0.0.1:9119

表示 Tailscale Serve 已設定將 HTTPS 流量轉送至本機 9119。

3. 故障排除流程

原始問題：

PLAIN
暫時無法連線此閘道，請檢查URL；
閘道回應後將顯示驗證方式。

3.1 排查決策樹

3.2 實際排查結果

4. 關鍵診斷指令

以下指令依本次實際排查順序排列。

4.1 關鍵錯誤

本機 API：

PLAIN
HTTP/1.1 200 OK

遠端 HTTPS：

PLAIN
HTTP/1.1 400 Bad Request

Invalid Host header.
Dashboard requests must use the bound hostname
or the configured public hostname.

使用相同 Host 標頭測試本機 API：

PLAIN
curl.exe -i -H "Host: xxxx.tailea6007.ts.net" http://127.0.0.1:9119/api/status

結果同樣為 400 Bad Request。

根因： Hermes Gateway 的 Host 驗證機制不接受尚未設定的 Tailscale 網域，而不是 Tailscale 無法連線。

5. 找出 Hermes 正確設定

5.1 確認 Gateway 啟動方式

PLAIN
hermes serve --status

實際結果：

PLAIN
hermes.exe serve --host 127.0.0.1 --port 9119

5.2 查閱 Hermes 原始碼

Windows Store 套件資訊：

PLAIN
Get-AppxPackage *HermesAgent* | Select-Object Name,Version,InstallLocation

本次找到：

PLAIN
hermes_cli/web_server.py
hermes_cli/web_server_boundary.py
hermes_cli/config_defaults.py
hermes_cli/main_dashboard.py

其中 web_server.py 第 389～391 行負責檢查 Host：

PLAIN
if bound_host and not _is_accepted_host(
    request.headers.get("host", ""),
    bound_host,
    getattr(app.state, "trusted_public_hosts", frozenset())
):

程式碼及設定註解確認：

安全機制： 設定非本機的公開網址後，Hermes 要求提供身分驗證；未設定驗證時，服務可能拒絕啟動。

6. 實際修復步驟

6.1 設定公開網址

在電腦 A：

PLAIN
hermes config set dashboard.public_url "https://xxxx.tailea6007.ts.net"

成功訊息：

PLAIN
✓ Set dashboard.public_url = https://xxxx.tailea6007.ts.net

6.2 停止舊 Gateway

PLAIN
hermes serve --stop

實際結果：

PLAIN
✓ stopped PID 25704

6.3 重新啟動 Gateway

PLAIN
hermes serve --host 127.0.0.1 --port 9119

Hermes 顯示驗證選項：

PLAIN
[1] Username & password
[2] OAuth via Nous Portal
[3] Cancel

選擇 1，依序設定帳號、密碼及確認密碼。

本次結果：

PLAIN
✓ Username/password auth configured (user: admin).
Saved to config.yaml under dashboard.basic_auth.

HERMES_BACKEND_READY port=9119
HERMES_DASHBOARD_READY port=9119
Hermes backend listening on 127.0.0.1:9119

密碼由 Hermes 處理並以雜湊形式保存，不需要手動修改 WindowsApps 程式檔。

6.4 驗證修復成功

在電腦 B：

PLAIN
curl.exe -i https://xxxx.tailea6007.ts.net/api/status

修復後結果：

PLAIN
{
  "gateway_running": true,
  "gateway_state": "running",
  "auth_required": true,
  "auth_providers": ["basic"],
  "overall": "ok"
}

代表 HTTPS、Gateway 及登入驗證皆正常。

7. Remote Hermes Desktop 連線設定

在電腦 B：

  1. 開啟 Hermes Desktop。

  2. 進入 Settings → Gateways。

  3. 選擇 Remote Gateway。

  4. 輸入：

PLAIN
https://xxxx.tailea6007.ts.net

  1. 選擇 Username & Password。

  2. 輸入電腦 A 設定的帳號密碼。

  3. 儲存並重新連線。

使用 Tailscale Serve 時，不需要在 HTTPS 網址後加 :9119，該連接埠由 Serve 在內部轉送。
